# Home Assistant Pi Firmware Updater v1.0.4 - Agent Tooling Refresh and Pinned CI Dependency Bump

No changes to the integration itself — SSH flow, entities, actions, and
firmware safety logic are identical to 1.0.3. This release refreshes the
project's agent/skill scaffolding and brings every pinned CI tool up to its
latest stable release.

## Highlights

- **New skill:** `runtime-troubleshooting` — a symptom-to-cause playbook for
  diagnosing a live install (SSH permission denied, stuck sensors, silent
  updates, uninstall leftovers) before routing to the skill that changes code.
- **New sidecar:** `CLAUDE.md`, pointing Claude Code at the canonical
  `AGENTS.md`, alongside the existing Copilot sidecar.
- **Release skill upgrade:** the release playbook now also writes the GitHub
  Release description file and stages the `vX.Y.Z` tag — with an explicit
  stop-and-confirm gate before anything is pushed or published.
- **CI dependency bump:** Python 3.12 → 3.14, Node.js 22.21.0 → 26.8.1,
  `docker/setup-buildx-action` v4.2.0 → v4.3.0, `hadolint` v2.14.0 → v2.15.1,
  `lizard` 1.23.0 → 1.24.0, `kcov` v42 → v43 — shared lint-tool pins match
  between `.github/workflows/test.yml` and `tests/Dockerfile`; complementary
  pins (Python, GitHub Actions, kcov) stay in the file that uses them.

## Install

- PyPI/pip not applicable — this is a HACS-compatible Home Assistant
  integration; copy `custom_components/pi_firmware_updater/` into your HA
  `config/custom_components/` directory, or install via HACS.
- Existing installs: no migration needed, integration behavior is unchanged.

## Validation

- `./tests/run_tests.sh lint` and full unit/component/e2e suites green
- Coverage: 93.70% (≥ 90% threshold)
