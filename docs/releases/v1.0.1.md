# Release v1.0.1

This release introduces safety-blocking mechanisms for Raspberry Pi firmware upgrades, provides fail-closed handling on supervisor API query failures, enhances user-facing notifications, and modernizes the CI/CD pipeline so that selected GitHub Actions now use the Node 24 runtime, eliminating Node 20 deprecation warnings.

## Key Changes

### 🚫 Upgrade Feasibility & Safety Blocking

- **Raspberry Pi 3/4 SSD Boot Protection**: Blocks firmware upgrades on Raspberry Pi 3/4-family devices (including standard boards, CM3/CM4, CM4S, and Pi 400) if booting from an NVMe SSD or USB SATA SSD to prevent potential bootloader incompatibilities.
- **Raspberry Pi 5 Allowed**: Safely permits NVMe/SSD boots on Raspberry Pi 5 models.
- **Fail-Closed Guards**: Halts and fails updates immediately if HA OS CLI queries fail, if JSON parsing fails, or if the boot device cannot be determined.

### 🔔 Robust Notification & Error Handling

- **Mobile Notification Fail-Safe**: Restructured `action_handler.yaml` to act on the immediate return status of `shell_command.apply_pi_firmware_update` for launch-time failures (for example, SSH command invocation errors). This status confirms whether Home Assistant successfully launched the host-side update command, not whether the later detached firmware flash completed successfully. Long-running update output and exit status are written to `/var/log/pi_firmware_update.log` on the host for post-execution diagnosis.
- **Alert Dismissal & Warnings**: Refined `apply_pi_firmware_update_script.yaml` to dismiss the `pi_firmware_blocked_alert` and send the 3-minute offline warning prior to update invocation.
- **Diagnostic Logging**: Configured detached background updates to write their outputs, errors, and exit status code to `/var/log/pi_firmware_update.log` for post-execution debugging.

### ⚙️ CI/CD Modernization (Node 24 Runtime)

- **Node 24 Runtime**: Upgraded artifact-handling actions to versions that run on the Node 24 runtime (`actions/upload-artifact@v6`, `actions/download-artifact@v6`), and retained already-current actions (`actions/cache@v5`, `docker/setup-buildx-action@v4`, `docker/build-push-action@v7`, `actions/checkout@v6`, `marocchino/sticky-pull-request-comment@v3`). This eliminates Node 20 deprecation warnings on GitHub-hosted runners.
- **Parallel Testing Matrix**: Restructured the workflow to run tests for `debian:bookworm-slim` and `debian:testing-slim` concurrently in a matrix job, optimizing execution speed.
- **Least-Privilege Scoping**: Configured top-level default permissions to `contents: read` and limited write permissions to only the `report-coverage` job.

### 🧪 Enhanced Test Coverage

- Overall test coverage has been driven to **94%** by implementing mock helpers and covering UUID/PARTUUID path resolutions, up-to-date checks, and error paths in `host_check_test.bats`.
