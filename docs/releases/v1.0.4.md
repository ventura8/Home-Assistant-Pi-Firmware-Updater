# v1.0.4 - Agent Tooling Refresh and Pinned CI Dependency Bump

## Summary

This release carries no changes to the Home Assistant integration itself
(`custom_components/pi_firmware_updater/`) — SSH flow, entities, actions, and
safety logic are unchanged from **1.0.3**. It refreshes the agent/skill
scaffolding used to develop the project and bumps every pinned CI tool to its
latest stable release. Shared lint-tool pins are kept identical between
`.github/workflows/test.yml` and `tests/Dockerfile` (with SHA256 verification
where applicable); each file also carries complementary pins (Python and
GitHub Actions in the workflow; kcov in the Dockerfile).

## Migration / Operational Impact

- **End users:** No action needed. Setup, SSH, and uninstall behavior are
  identical to 1.0.3.
- **Contributors:** CI now builds with newer pinned tool versions (see table
  below). Re-pull `tests/Dockerfile`'s base layers before running the local
  Docker test suite so the new pins are used.

## Key Changes

### 1. Agent tooling scaffolding

- Added `CLAUDE.md`, a thin sidecar pointing Claude Code at the canonical
  `AGENTS.md` (mirrors the existing Copilot sidecar pattern).
- Added skill `.github/skills/runtime-troubleshooting/SKILL.md` — a
  symptom-to-cause playbook for diagnosing a *live* install (SSH permission
  denied, stuck sensors, silent updates, uninstall leftovers) before routing
  to the skill that actually changes code.
- Wired the new skill into `AGENTS.md`, `.agent/agents.md`,
  `.github/agents/project.agent.md`, and `.github/skills/README.md`.
- Extended `.github/skills/release-doc-and-badge-update/SKILL.md` and
  `.agent/workflows/release.md` to cover writing the GitHub Release
  description file and cutting the `vX.Y.Z` tag, with an explicit stop-and-
  confirm gate before pushing the tag or publishing the release.

### 2. Pinned CI dependency updates

All versions below were verified against upstream latest stable releases.
Shared lint-tool pins match between `.github/workflows/test.yml` (lint job) and
`tests/Dockerfile` (coverage/test image), with SHA256 checksums where
checksum-verified; complementary pins (Python, GitHub Actions, kcov) live in
the file that consumes them.

| Tool | 1.0.3 | 1.0.4 | Pin location |
| --- | --- | --- | --- |
| Python (lint job) | 3.12 | 3.14 | workflow only |
| Node.js (markdownlint-cli runtime) | 22.21.0 | 26.8.1 | workflow + Dockerfile |
| `docker/setup-buildx-action` | v4.2.0 | v4.3.0 | workflow only |
| `hadolint` | v2.14.0 | v2.15.1 | workflow + Dockerfile |
| `lizard` | 1.23.0 | 1.24.0 | workflow + Dockerfile |
| `kcov` | v42 | v43 | Dockerfile only |

Unchanged (already latest stable): `actions/checkout`, `actions/setup-python`,
`actions/setup-node`, `actions/cache`, `docker/build-push-action`,
`actions/upload-artifact`, `actions/download-artifact`,
`marocchino/sticky-pull-request-comment`, `shellcheck`, `shfmt`,
`actionlint`, `yamllint`, `markdownlint-cli`.

### 3. Version

- `custom_components/pi_firmware_updater/manifest.json` version set to
  **1.0.4**.

### 4. Coverage

- Full local Docker lint + unit/component/e2e coverage run against the
  rebuilt image: **93.70%** overall (badge unchanged at 93% — no product
  code touched, so `assets/coverage.svg` is not part of this change set).

## Notes

- `actionlint` requires the checked-out `.github/workflows` directory and is
  intentionally run on the GitHub Actions runner directly (not inside the
  Docker test image, which excludes `.git`/`.github` via `.dockerignore`) —
  unchanged CI behavior, not a regression from this release.
- No entity, action, or SSH contract changes; the "Home Assistant Contract
  Stability" and "Install / Uninstall Invariants" sections of `AGENTS.md`
  are unaffected.
