# v1.0.5 - Installer Public-Key Hardening

## Summary

Security patch for `install.sh`. Previously, public-key validation inspected
only the first line of `/config/.ssh/id_rsa.pub`, while the `authorized_keys`
line and stored key blob were built from the **entire** file. A second key
line planted in `id_rsa.pub` (by any component with `/config` write access)
therefore passed validation and was appended to the host's
`/root/.ssh/authorized_keys` as a separate entry **without** the
`restrict,from="127.0.0.1",command=...` prefix — an unrestricted root key on
port 22222 after the next documented "safe refresh" re-run of the installer.

No entity, action, YAML, or SSH-contract changes. Single-line `ssh-keygen`
output (the normal case) is authorized exactly as before.

## Migration / Operational Impact

- **End users:** Re-run `bash /config/custom_components/pi_firmware_updater/install.sh`
  once after updating to refresh the host. If your `id_rsa.pub` was ever
  hand-edited to contain more than one key line, the installer now aborts with
  `Public key file must contain exactly one key line` — remove the extra
  lines (or delete `id_rsa.pub` and let the installer regenerate it from
  `id_rsa`) and re-run.
- **Anyone who ran the vulnerable installer with a multi-line `id_rsa.pub`:**
  inspect `/root/.ssh/authorized_keys` on the host (port 22222) and remove any
  entry that lacks the `restrict,from="127.0.0.1",command=` prefix and is not
  your own admin key.
- **Contributors:** New install invariant recorded in `AGENTS.md`; component
  tests cover the rejection paths.

## Key Changes

### 1. `install.sh` — single validated record only

- `validate_public_key()` now requires **exactly one** non-blank line in
  `id_rsa.pub`, parses type and blob from that record (not physical line 1),
  keeps the supported-type / ≥ 32-char checks, and rejects any blob character
  outside `[A-Za-z0-9+/=]`.
- Validated fields are held in `PUB_KEY_TYPE` / `PUB_KEY_BLOB`; the restricted
  `authorized_keys` line and `key.blob` are built solely from those. Raw file
  contents never reach the remote bootstrap script.
- The base64-only guard also closes a latent single-quote escape in the remote
  `awk -v blob='…'` / `printf '…'` quoting.

### 2. Tests

Five new component tests in `tests/component/install_test.bats`:

- multi-line pub rejected before any SSH stdin write
- non-base64 blob rejected
- unsupported key type rejected
- single record surrounded by blank lines accepted
- pushed `AUTH` heredoc contains exactly one restricted line built from the
  validated fields
