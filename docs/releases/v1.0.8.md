# v1.0.8 - SonarQube Cloud Coverage Import

## Summary

CI release. Switches SonarQube Cloud from Automatic Analysis to CI-based
analysis so the kcov coverage report is imported, and adds a manual trigger to
the test workflow.

**No runtime behavior changes for end users.** Nothing under
`custom_components/` changes except the manifest version.

## Migration / Operational Impact

- **End users:** nothing to do. No installer re-run, no host state changes.
- **Maintainers:** SonarQube Cloud now runs from the `sonarqube` job in
  `test.yml`. It needs the `SONAR_TOKEN` secret, the `SONAR_CI_ANALYSIS=true`
  repository variable, and Automatic Analysis turned off (all done). Forked and
  Dependabot PRs still get no SonarQube analysis because they cannot read the
  secret.

## Key Changes

### 1. `workflow_dispatch` on Run Tests

`test.yml` can now be started from **Actions -> Run Tests -> Run workflow**.
Re-running an older run keeps that run's original variables, so after adding
`SONAR_CI_ANALYSIS` the `sonarqube` job stayed skipped on re-runs. A manual run
is a fresh run and picks the variable up.

### 2. Documentation

`docs/development_standards.md` marks CI-based analysis as the active mode and
adds the "start a fresh run" step to the switchover.

### 3. Version

- `custom_components/pi_firmware_updater/manifest.json` version set to
  **1.0.8**.

### 4. Coverage

- **93.90%** overall, unchanged (badge unchanged at 93%). SonarQube Cloud now
  receives this figure.
