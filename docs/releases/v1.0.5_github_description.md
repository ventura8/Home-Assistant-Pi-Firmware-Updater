# Home Assistant Pi Firmware Updater v1.0.5 - Installer Public-Key Hardening

Security patch for `install.sh`. Public-key validation previously checked only
the first line of `/config/.ssh/id_rsa.pub` while the host `authorized_keys`
entry was built from the whole file, so an extra key line planted in that file
could land on the host as an **unrestricted root key** on the next installer
run. The installer now authorizes exactly one validated key record.

## Highlights

- **Single-record validation:** `id_rsa.pub` must contain exactly one
  non-blank line with a supported key type and a base64-only blob (≥ 32
  chars); anything else aborts before any host change.
- **Auth line built from validated fields only:** raw file contents never
  reach the remote bootstrap script (also closes a latent quote-escape in the
  remote `awk`/`printf`).
- **Tests:** five new component tests covering the rejection paths, the
  blank-line-tolerant accept path, and the exact restricted line pushed.
- **CI bumps:** `softprops/action-gh-release` 3.0.3,
  `docker/build-push-action` 7.4.0, `docker/setup-buildx-action` 4.4.1.

## Upgrade

- Update via HACS (or copy `custom_components/pi_firmware_updater/`), then
  re-run `bash /config/custom_components/pi_firmware_updater/install.sh` once
  to refresh the host.
- If you ever ran the installer with a hand-edited multi-line `id_rsa.pub`,
  check `/root/.ssh/authorized_keys` on the host and remove any entry that
  lacks the `restrict,from="127.0.0.1",command=` prefix and is not your own
  admin key.
- No entity, action, or YAML changes.
