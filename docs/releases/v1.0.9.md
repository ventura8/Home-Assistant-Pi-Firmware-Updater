# v1.0.9 - Exact-Match Host Key Cleanup and Dependency Refresh

## Summary

Security fix for the installer plus a dependency refresh. A planted
`/config/.ssh/id_rsa.pub` with a short blob could make `install.sh` delete
unrelated host SSH keys on port 22222. The installer now trusts the public key
only when it matches `id_rsa`, and host cleanup only removes exact key matches.

## Security Fix: authorized_keys cleanup could wipe unrelated host keys

**Severity:** medium. **Precondition:** an attacker can already write to
`/config/` (for example a malicious or compromised custom component), and the
user re-runs `install.sh`.

Before this release:

- `validate_public_key()` accepted any single-line pub whose blob was at least
  32 base64 characters. It never checked that the blob was a complete key or
  that it belonged to `/config/.ssh/id_rsa`.
- The password-bootstrap refresh removed every host `authorized_keys` line that
  contained the blob anywhere (`awk index($0, blob)`). A 32-character prefix
  shared by typical 2048-bit `ssh-rsa` keys (for example
  `AAAAB3NzaC1yc2EAAAADAQABAAABAQC3`) matched and deleted those admin keys.
- The host wrapper's `pi_firmware_uninstall` used the same substring rule.

Now:

- `id_rsa.pub` type and blob must equal what `ssh-keygen -y -f id_rsa`
  derives. A mismatched pub aborts with
  `id_rsa.pub does not match id_rsa` before any host change. If the pub cannot
  be derived, install also aborts.
- Blobs shorter than 68 base64 characters (the shortest real key, ed25519) are
  rejected.
- Host cleanup in `install.sh` and `ssh_wrapper.sh` drops lines that reference
  the wrapper path, plus lines with a whitespace-separated field **exactly
  equal** to the managed blob (`$i == blob`). Keys that only share a prefix
  survive.
- Behavior change: host-side `pi_firmware_uninstall` now also removes an
  unrestricted copy of the integration key (exact blob match), matching what
  the installer already did on refresh.

## Migration / Operational Impact

- **End users:** update, then re-run
  `bash /config/custom_components/pi_firmware_updater/install.sh` so the host
  gets the fixed `ssh_wrapper.sh`.
- If install now stops with `id_rsa.pub does not match id_rsa`, find out what
  wrote `/config/.ssh/id_rsa.pub`. Then delete it and re-run `install.sh` to
  regenerate it from `id_rsa`.
- **Maintainers:** the `ssh-keygen` test mock now treats a private key file
  that contains a public key line as that key, so `-y` returns it. An empty
  private key file still recovers the fixed default key.
  `MOCK_SSH_KEYGEN_DERIVE_FAIL=true` forces `-y` to fail.

## Tests Added

- Truncated 32-character `ssh-rsa` prefix blob is rejected before any host
  mutation
- `id_rsa.pub` that does not match `id_rsa` is rejected
- Install aborts when the public key cannot be derived from `id_rsa`
- The real refresh payload, run against a sample `authorized_keys`, keeps an
  admin key that shares the managed blob as a prefix and an ed25519 key. It
  drops the stale managed line and an exact unrestricted copy, and leaves
  exactly one wrapper line
- Wrapper `pi_firmware_uninstall` keeps prefix-sharing keys
