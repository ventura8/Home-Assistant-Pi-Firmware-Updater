# v1.0.3 - Restricted Host SSH Access and Uninstall Cleanup

## Summary

This release hardens the host SSH trust relationship used by the integration:
passphrase-less RSA keys remain (required for unattended Home Assistant
`shell_command` use), but host `authorized_keys` entries are now localhost-bound
and forced through a command allowlist wrapper. Uninstall removes the host
authorization and wrapper before deleting local keys. Documentation and agent
playbooks are updated accordingly, and `manifest.json` is aligned to **1.0.3**.

Also includes the Dependabot bump of `docker/build-push-action` to v7.3.0 on the
release branch.

## Migration / Operational Impact

- **Existing installs:** Re-run
  `bash /config/custom_components/pi_firmware_updater/install.sh` to replace any
  unrestricted host `authorized_keys` line with the restricted entry and deploy
  `/root/.pi_firmware_updater/ssh_wrapper.sh`. Key regeneration is not required
  when `/config/.ssh/id_rsa` already exists.
- **Uninstall:** Prefer the updated `uninstall.sh` so host cleanup runs while the
  private key is still present. If SSH cleanup fails, follow the printed manual
  steps to remove `pi_firmware_updater` lines from `/root/.ssh/authorized_keys`
  and delete `/root/.pi_firmware_updater/`.
- **Backups:** Treat Home Assistant full backups as sensitive — they include
  `/config/.ssh/id_rsa` by default.

## Key Changes

### 1. Restricted host SSH authorization

- `install.sh` generates keys with comment/marker `pi_firmware_updater`.
- Deploys host wrapper `/root/.pi_firmware_updater/ssh_wrapper.sh`.
- Upserts restricted `authorized_keys` line:
  `restrict,from="127.0.0.1",command="/root/.pi_firmware_updater/ssh_wrapper.sh" ...`
- Wrapper allowlists fixed ops only (`pi_firmware_check`, `pi_firmware_update`,
  `pi_firmware_uninstall`, `exit`) and never executes caller stdin as a shell
  program. Deploy ops are not allowlisted; install uses password bootstrap.
- Shell commands invoke `pi_firmware_check` / `pi_firmware_update` (no stdin pipe).
- Managed auth-line removal matches key blob + wrapper path.
- Re-running install refreshes wrapper + `authorized_keys` even when key auth
  already works (upgrade path for older unrestricted installs).

### 2. Uninstall host cleanup

- `uninstall.sh` removes managed host `authorized_keys` entries and the wrapper
  directory **before** deleting local keys.
- Warns with manual remediation steps and continues local cleanup if host SSH
  cleanup fails.

### 3. Tests and mocks

- Extended `tests/mocks/ssh` and `tests/mocks/ssh-keygen` for authorize/cleanup

### 4. Documentation and agent law
