# v1.0.6 - SonarQube Cloud Integration and Workflow Hardening

## Summary

Tooling and CI release. Adds SonarQube Cloud static analysis to the project and
resolves 101 of the 104 issues its first analysis reported.

The one security-relevant finding is in `.github/workflows/release.yml`: the
`workflow_dispatch` `tag` input was interpolated directly into a `run` block,
so a crafted tag value could execute arbitrary shell in the release job. The
tag-shape validation that follows ran *after* the injection point. Inputs are
now bound to environment variables.

**No runtime behavior changes for end users.** No entity, action, YAML, SSH
contract, or install/uninstall flow changes. Error messages emitted by
`host_check.sh` and `install.sh` on failure paths now go to stderr instead of
stdout; both are forwarded over SSH, and the sensor payload path
(`emit_summary`) is untouched.

## Migration / Operational Impact

- **End users:** nothing to do. Update via HACS when convenient. No installer
  re-run is required and no host state changes.
- **Contributors:** `./scripts/sonar_scan.sh` runs a local analysis. New
  invariants are recorded in `AGENTS.md` under *Static analysis*. Default
  `case` branches must be written `*) : ;;` — see below.

## Key Changes

### 1. `release.yml` — script injection fix

`inputs.tag`, `github.event_name`, and `github.ref_name` are bound through
`env:` and referenced as shell variables rather than interpolated into the
script body. The `steps.meta.outputs.*` reads in the validation step were
given the same treatment.

### 2. SonarQube Cloud integration

- `sonar-project.properties` — source/test split, exclusions, coverage path
- `scripts/sonar_scan.sh` — local analysis via `sonar-scanner-cli` in Docker
- `sonarqube` job in `test.yml`, chained off `report-coverage`

kcov records container-absolute paths (`/app/...`) in its report. Sonar would
match none of them against source files, so both the CI job and the local
script rewrite them to repository-relative first.

Two analysis modes exist and only one may be active at a time. Automatic
Analysis is currently enabled: no token, no CI job, but no coverage import.
The CI job is gated on the `SONAR_CI_ANALYSIS` repository variable and stays
inert until a `SONAR_TOKEN` secret is added and Automatic Analysis is turned
off. Documented in `docs/development_standards.md`.

### 3. Shell fixes from the analysis

| Rule | Count | Change |
| --- | ---: | --- |
| `S7688` | 47 | `[ ]` -> `[[ ]]` |
| `S7677` | 17 | Error messages redirected to stderr |
| `S131` | 3 | Default `case` branches |
| `S7684` | 2 | `lower_case` local variable names |
| `S1192` | 2 | Named constants for repeated literals |
| `S7679` | 1 | Positional parameter bound to a local |

The `[ ]` -> `[[ ]]` conversion was applied only to the lines Sonar flagged. A
blanket rewrite would have corrupted the embedded Python heredocs in
`tests/run_tests.sh`, the `*[!A-Za-z0-9+/=]*` glob in `install.sh`, and the
generated command text inside the quoted heredocs in `host_check.sh`.

`BOOT_STATUS_ALLOWED` and `VALUE_UNKNOWN` hold literals that appear in the
sensor payload; their values are unchanged.

### 4. CI and container hardening

- Third-party actions pinned to commit SHAs, tag retained as a trailing
  comment so Dependabot still tracks them (`S7637`)
- `curl` transfers pinned to https with `--proto '=https' --tlsv1.2` (`S6506`)
- `pip install --only-binary :all:` and `npm install --ignore-scripts`
  (`S8541`, `S6505`); both tools ship wheels and markdownlint-cli declares no
  lifecycle scripts, verified before the flags were added
- `apt-get install --no-install-recommends`, package list sorted (`S6500`,
  `S7018`)
- `wget` replaced with `curl` for the kcov download, so every download in the
  image uses one protocol-pinned tool

This also cleared three hadolint findings (DL3015, DL3047, DL4001) with none
added.

### 5. Dependency updates

| Dependency | 1.0.5 | 1.0.6 |
| --- | --- | --- |
| `shfmt` | v3.13.1 | v3.14.1 |
| Node.js | 26.8.1 | 26.10.0 |
| `SonarSource/sonarqube-scan-action` | — | v8.2.2 |

Both carry refreshed `sha256` pins. `mvdan/sh` publishes no checksum file for
v3.14.1, so the binary was downloaded and hashed directly, and confirmed to
reformat nothing in the tree before the pin moved.

Note that Dependabot covers `github-actions` and `docker` but not the pinned
tool versions in the `tests/Dockerfile` `ARG` block; those move by hand.

### 6. Issues deliberately not fixed (3)

`docker:S7026` x3 — "replace this invocation of curl with the ADD
instruction". The three downloads it flags are checksum-verified
(`curl` + `sha256sum -c`). `ADD` would not preserve that verification, so the
current form is kept.

### 7. Version

- `custom_components/pi_firmware_updater/manifest.json` version set to
  **1.0.6**.

### 8. Coverage

- **93.90%** overall, down from 94.40% at v1.0.5 (badge 94% -> 93%), above the
  90% threshold.

The delta is two lines in `install.sh` (the non-base64 blob rejection `echo`
and its `exit 1`). That path is still exercised — the component test
`Rejects public key blob with non-base64 characters` runs it and asserts the
message, verified directly — but kcov stops attributing those two lines after
the change. No test was removed or weakened.

A related finding is recorded in `AGENTS.md`: a bare `*) ;;` default case
satisfies Sonar S131 but kcov cannot attribute it, which silently cost three
more lines. Writing `*) : ;;` gives kcov a real command to record and
recovered them.
