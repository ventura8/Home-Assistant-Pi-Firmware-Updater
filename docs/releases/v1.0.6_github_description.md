# Home Assistant Pi Firmware Updater v1.0.6 - SonarQube Cloud Integration and Workflow Hardening

Tooling and CI release. Adds SonarQube Cloud static analysis and fixes 96 of
the 104 issues its first analysis reported. The 8 that remain are all in the
test-only `tests/Dockerfile` and are deliberate.

The one security-relevant finding is in the release workflow: the
`workflow_dispatch` `tag` input was interpolated directly into a `run` block,
so a crafted tag value could execute arbitrary shell in the release job — the
tag-shape validation ran *after* the injection point. Inputs are now bound to
environment variables.

**No runtime changes for end users.** No entity, action, YAML, SSH contract,
or install/uninstall changes. Nothing to do on upgrade.

## Highlights

- **Script injection fix** in `.github/workflows/release.yml` (`S7630`,
  blocker).
- **SonarQube Cloud wired up:** `sonar-project.properties`, a local
  `scripts/sonar_scan.sh` that runs the scanner in Docker, and a CI job that
  imports kcov coverage. kcov writes container-absolute paths, which Sonar
  would match against nothing, so both paths rewrite them first.
- **Shell cleanups:** `[[ ]]` conditionals, error output to stderr, default
  `case` branches, named constants for repeated sensor literals. Applied only
  to flagged lines — a blanket rewrite would have corrupted embedded Python
  heredocs and glob patterns.
- **Supply-chain hardening:** third-party actions pinned to commit SHAs,
  https-pinned `curl` transfers, `pip --only-binary`, `npm --ignore-scripts`,
  `apt-get --no-install-recommends`. Also cleared three hadolint findings.
- **Dependency bumps:** `shfmt` 3.14.1, Node.js 26.10.0,
  `sonarqube-scan-action` 8.2.2, with refreshed sha256 pins.

## Upgrade

- Update via HACS (or copy `custom_components/pi_firmware_updater/`).
- **No installer re-run required.** No host state changes.

## Notes

- Eight issues are deliberately unfixed, all in the test-only
  `tests/Dockerfile`: `ADD` in place of checksum-verified `curl` (3), merging
  the kcov build steps that are split for debuggability (3), the container
  running as root (it must, to write `/root/.ssh`), and the recursive `COPY`
  that gives the image the repo under test. The quality gate is green with
  these open.
- Coverage is 93.90%, down from 94.40% (badge 94% -> 93%), above the 90%
  threshold. The delta is two lines in `install.sh` that kcov stopped
  attributing; the path is still exercised by a passing component test that
  asserts the exact message. No test was removed or weakened.
