# v1.0.7 - Test Image SonarQube Cleanup

## Summary

Tooling release. Resolves the 8 SonarQube Cloud issues left open in v1.0.6,
all in `tests/Dockerfile` (the test-only container). The project now has **0
open issues** and 0 security hotspots.

v1.0.6 kept these open because the obvious fixes would have lost something.
This release fixes all eight without losing anything: downloads are still
checksum-verified, and the test container runs as a normal user instead of
root.

**No runtime behavior changes for end users.** Nothing under
`custom_components/` changes except the manifest version.

## Migration / Operational Impact

- **End users:** nothing to do. Update via HACS when convenient. No installer
  re-run is required and no host state changes.
- **Contributors on Linux:** the test image now runs as UID/GID 1001 by
  default. `scripts/run_local_tests.ps1` and `scripts/run_coverage.ps1` pass
  the host's `id -u`/`id -g` automatically. For a manual `docker build`, add
  `--build-arg TEST_UID=$(id -u) --build-arg TEST_GID=$(id -g)` before
  mounting host directories. Docker Desktop needs nothing.

## Key Changes

### 1. `tests/Dockerfile`

| Rule | Count | Change |
| --- | ---: | --- |
| `docker:S7026` | 3 | `curl` + `sha256sum -c` replaced by `ADD --checksum=sha256:...`; every pinned download is still verified |
| `docker:S7031` | 3 | Consecutive `RUN` steps (apt, tool unpacking, pip/npm, kcov build and cleanup) merged into one layer |
| `docker:S6470` | 1 | `COPY . /app/` replaced by copies of `custom_components/` and `tests/` only; the lint gate already runs against the mounted workspace |
| `docker:S6471` | 1 | Image ends as an unprivileged `tester` user (`TEST_UID`/`TEST_GID`, default 1001) |

The non-root user owns the paths the suites write to: the mock `/config`
tree, `/app`, `/var/log/pi_firmware_update.log`, and `/root`. In the test
image, `/root` stands in for the Home Assistant host's root home that
`ssh_wrapper.sh` manages. No product script or test changed to accommodate
the user.

The Dockerfile now declares `# syntax=docker/dockerfile:1` so `ADD
--checksum` and `${VAR#prefix}` expansion work regardless of the engine's
bundled frontend.

### 2. CI and local runners

- `test.yml` builds both the matrix image and the merge image with the
  runner's UID/GID, so bind-mounted coverage directories stay writable.
- `run_local_tests.ps1` and `run_coverage.ps1` pass the host UID/GID on
  Linux, and create `coverage/` before mounting it. Docker creates a missing
  mount source owned by root, which the unprivileged user cannot write.

### 3. Version

- `custom_components/pi_firmware_updater/manifest.json` version set to
  **1.0.7**.

### 4. Coverage

- **93.90%** overall, unchanged from v1.0.6 (badge unchanged at 93%).
